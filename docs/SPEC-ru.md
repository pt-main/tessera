# Tessera

Tessera - простой портируемый язык хранения данных. И его простота - его главное преимущество. Каноничная реализация языка написана на Rust, зависимости можно посмотреть в `Cargo.toml` проекта. Все ядро - структура и парсер в эту структуру умещаются в 200 строк. При этом, скорость на данный момент на уровне 160 МБ/с в пике, и около 120 МБ/с на сложных задачах (1м+ строк вложенных структур, к примеру). Он создан для максимальной простоты работы с данными при человекочитаемости и возможности оптимизации. Разберем концепции и синтаксис языка.

## Семантика и идея

Язык разрабатывался в первую очередь, как было упомянуто, для максимальной простоты и при этом скорости. Поэтому, были использованы следующие компромиссы -

- Все - есть таблица: В языке намеренно нет массивов (если не считать байты). Это сделано для упрощения парсинга и за ненадобностью в рамках концепции.
- Значения строго типизированы (для скорости парсинга, очевидно).
- Синтаксис построчный, и не поддерживает запись в одну строку (для простоты парсинга и за ненадобностью).

## Модель данных

Таблица - неупорядоченный набор именованных значений, сгруппированных по типу. Один ключ может лежать одновременно в разных типовых таблицах. Если ключ повторяется в одной таблице - побеждает последнее значение.

| Таблица | Тип значения |
| :- | :- |
| ints   | `i64` |
| strs   | UTF-8 строка |
| floats | `f64` |
| bytes  | байты, `Vec<u8>` |
| logicals  | `bool` |
| inners | вложенная таблица |

Корневая таблица неявная и существует всегда. Вложенность не ограничена. Порядок ключей не сохраняется.

## Синтаксис

Синтаксис языка минимален, и очень прост, что позволяет уместить всю логику обработки в 150 строк Rust кода. Всё, что можно написать в файле - это четыре конструкции.

**Конструкции:**

| Синтаксис | Что делает | Ньюансы | Почему так |
| :- | :- | :- | :- |
| `key type value` | Поле текущей таблицы. | `key` и `type` не могут содержать пробелы. Тип - только один символ. `value` - всё после второго пробела, поэтому может содержать пробелы. Разделитель - ровно один пробел `' '`. Дубликаты перезаписываются. | Основная единица данных. |
| `<name` | Открывает вложенную таблицу `name`. | `name` - остаток строки после `<`, обрезанный по краям. Может содержать пробелы. Пустое имя - `MissingName`. | Вложенность без скобок и отступов. |
| `>` | Закрывает текущую вложенную таблицу. | Строка должна быть ровно `>` после trim. Если закрывать нечего - `CantPopStack`. | Симметрично `<`. |
| `# ...` | Комментарий до конца строки. | Только если `#` - первый непробельный символ. Inline-комментариев нет. | Простота. |
| пустая строка | Игнорируется. | После trim. | Удобство форматирования. |
| EOF | Автоматически закрывает все открытые таблицы. | Не ошибка. | Упрощает парсер и ручное написание. |

## Типы

| Тип | Rust-тип | Как парсится | Нюансы |
| :- | :- | :- | :- |
| `i` | `i64` | `value.parse::<i64>()` | Десятичное число. Ведущий `+`/`-` можно. Пробелы внутри значения не допускаются. Ошибка - `InvalidInt`. |
| `f` | `f64` | `value.parse::<f64>()` | `1.0`, `-2.5`, `1e10`, `2.5E-3`. Пробелы внутри значения не допускаются. Ошибка - `InvalidFloat`. |
| `s` | `CompactString` | снимаются внешние `"`, затем `unescape_default` | Если кавычек нет - значение берётся как есть, но escape всё равно обрабатывается. Ошибка - `BadEscape`. |
| `b` | `Vec<u8>` | `base64::engine::general_purpose::STANDARD.decode` | Стандартный Base64 с padding `=`. Пробелы внутри значения не допускаются. Ошибка - `BadBase64`. |
| `l` | `bool` | сравнение со строкой | `true` / `false` / `1` / `0`. Значение обрезается по краям. Иные значения - `InvalidBool`. |

### Escape в `f`

| Escape | Значение |
| :- | :- |
| `\\` | обратный слэш |
| `\"` | двойная кавычка |
| `\n` | перевод строки |
| `\r` | возврат каретки |
| `\t` | таб |
| `\uXXXX` | кодовая точка Unicode, 4 hex-цифры |

## Вложенность

Открытие таблицы:

```tessera
<name
```

`name` - остаток строки после `<`, обрезанный по краям. Может содержать пробелы.

Закрытие таблицы:

```tessera
>
```

Строка должна быть ровно `>` после trim.

Правила:

- всё, что до первого `<`, попадает в корневую таблицу;
- ключ, под которым вложенная таблица кладётся в родителя - это `name`;
- если таблица с таким ключом уже есть в `inners` родителя - она перезаписывается;
- если блоки не закрыты до конца файла - они закрываются автоматически при EOF. Это не ошибка.

## Парсинг

Парсер построчный. Используется `code.lines()`. Каждая строка обрезается через `trim_ascii()`.

Алгоритм:

1. Пустая строка - пропуск.
2. Строка начинается с `<` - открытие блока:
   - имя = остаток после `<`, обрезанный по краям;
   - если имя пустое - `MissingName`;
   - иначе новый `Config` кладётся на стек.
3. Строка равна `>` - закрытие блока:
   - если стек вложенности пуст (остался только корень) - `CantPopStack`;
   - иначе верхний `Config` достаётся из стека и вставляется в `inners` родителя.
4. Строка начинается с `#` - комментарий, пропуск.
5. Иначе строка режется `splitn(3, ' ')`:
   - если не три части - `MissingParts`;
   - `name`, `vtype`, `value`.
6. По `vtype`:
   - `i` -> `parse::<i64>()`;
   - `s` -> снять внешние `"`, затем `unescape_default`;
   - `f` -> `parse::<f64>()`;
   - `b` -> Base64 decode;
   - `l` -> `true` / `false` / `1` / `0`;
   - иначе -> `UnknownType`.
7. В конце файла все незакрытые блоки автоматически закрываются:
   - пока стек больше 1, верхний `Config` вставляется в `inners` родителя;
   - корневой `Config` записывается в `cfg`.

Ошибочное поле не добавляется в `Config`.  
Ошибочный блок не открывается.  
Ошибочное закрытие игнорируется.

## Ошибки

Парсер не падает на первой ошибке. Он собирает список ошибок и продолжает разбор.

| Ошибка | Когда возникает |
| :- | :- |
| `MissingName` | `<` без имени. |
| `CantPopStack` | `>` при пустом стеке вложенности. |
| `MissingParts` | Строка не соответствует `key type value`. |
| `InvalidInt` | Значение не парсится как `i64`. |
| `InvalidFloat` | Значение не парсится как `f64`. |
| `InvalidBool` | Значение не `true`, `false`, `1` или `0`. |
| `BadEscape` | Ошибка escape в `s`. |
| `BadBase64` | Ошибка Base64 в `b`. |
| `UnknownType` | Неизвестный тип. |

## Краткая грамматика

```ebnf
document    = { line } ;
line        = ws, (comment | block_open | block_close | field | empty), ws ;
block_open  = "<", ws, name, ws ;
block_close = ">" ;
field       = key, " ", type, " ", value ;
type        = "i" | "f" | "s" | "b" | "l" ;
comment     = "#", { any } ;
```

Где:

- `key` - непустая строка без пробелов;
- `value` - остаток строки после второго пробела;
- `name` - остаток строки после `<`, обрезанный по краям;
- `empty` - пустая строка или строка только из пробельных символов.

## Пример полного документа

```tessera
# Корневые поля
version i 1
title s "Example"
debug l true

<server
  host s "example.com"
  port i 8080
  <tls
    enabled l true
    cert b TUlJQ...
  >
>

<users
  <alice
    age i 30
    roles s "admin,user"
  >
>
```

При EOF все открытые блоки будут закрыты автоматически.
